Part 3 · Bytes 19–20

The bandit problem

Lecture 2 assumed the agent knows the dynamics \(p(s', r \mid s, a)\) and can plan without acting. Now we drop that assumption. To study learning from trial and error on its own, we first strip the MDP down to a single state: the bandit.

19The k-armed bandit problem

Motivation

In Lecture 2 the agent knew \(p(s', r \mid s, a)\), so it could compute the best policy with dynamic programming before taking a single action. Suppose instead that the agent does not know what its actions pay. The only way to find out is to try actions and watch the rewards. That raises a question DP never faced: should the agent use the action that has looked best so far, or try another one that might be better? To study this question without the complication of changing states, we use the simplest possible setting: one state, \(k\) actions, repeated many times.

Where the name comes from supplement

The name comes from casinos, but you do not need to know anything about gambling to follow this lecture. Here is the whole story in one picture.

Only the decision structure matters here, not the casino: several options, each with an unknown average payoff, chosen again and again, with feedback only on the option you chose. In this course an "arm" simply means "an action you can choose", and a "pull" means "choosing it once and seeing its reward".

Definition

A k-armed bandit is a repeated choice. At each step \(t = 1, 2, 3, \ldots\):

  1. The agent chooses one of \(k\) actions, called arms: \(A_t \in \{a_1, \ldots, a_k\}\).
  2. The environment returns a reward \(R_t\), drawn from a fixed probability distribution that belongs to the chosen arm.
  3. Nothing else changes. The next step offers the same \(k\) arms with the same distributions.

Each arm has a true action value, its expected reward:

$$q_*(a) = \mathbb{E}\big[\,R_t \mid A_t = a\,\big]$$
\(q_*(a)\) is the average reward arm \(a\) would pay over infinitely many pulls. It is a fixed number, and the agent does not know it. The expectation \(\mathbb{E}[\,\cdot \mid A_t = a]\) is over that arm's reward distribution (Byte B2). \(R_t\) carries the same index \(t\) as \(A_t\) because nothing happens between choosing and being paid; this is the usual bandit convention (in an MDP we wrote \(R_{t+1}\)).

The best arm and its value are

$$a^{*} = \arg\max_{a}\, q_*(a), \qquad q_*(a^{*}) = \max_{a}\, q_*(a)$$

If the agent knew \(q_*\), the problem would be trivial: always choose \(a^{*}\). The whole difficulty is that \(q_*\) is unknown and every reward is noisy, so the agent must learn \(q_*\) from the very rewards it is trying to maximize.

Historically, the clinical-trial setting came first: W. R. Thompson (1933) asked how to allocate patients between two treatments when the better one is unknown, and H. Robbins (1952) stated the general problem of sequential choice that became known as the multi-armed bandit. Real systems usually add complications (rewards that drift over time, context about each user, delayed feedback); these notes study the basic version first.

How the bandit relates to the MDP

A bandit is an MDP with a single state, \(|\mathcal{S}| = 1\). Since every action leads back to that same state, the future looks identical whatever you choose, so the best action is simply the one with the highest expected immediate reward. In Lecture 1's notation, \(q_*(a)\) is the expected reward \(R(s,a)\) of the single state (Byte 2), and no Bellman recursion is needed. What makes bandits hard is not planning ahead but not knowing.

Intuition

Think of choosing where to eat lunch near campus every day. You have a favourite place that is reliably good. There is also a new place you have tried only once; that one meal was poor, but one meal tells you little. Each day you either exploit (go to the favourite and get a good lunch for sure) or explore (try the new place and learn whether it is actually better). Explore too little and you may never find the best place; explore too much and you eat many poor lunches. Bytes 20–27 turn this trade-off into precise strategies.

Worked numeric example: the drone's route choice

Each morning the delivery drone from Lectures 1–2 picks one of \(k = 4\) routes for its first delivery. A delivery earns \(r = 2\) if it is on time, \(r = 0.5\) if it is late, and \(r = 0\) if it fails. The probabilities below are teaching choices, not measurements, and the drone does not know them.

River0.40.40.2\(0.80 + 0.20 + 0 = \mathbf{1.00}\)
Market0.50.40.1\(1.00 + 0.20 + 0 = \mathbf{1.20}\)
Hill0.20.60.2\(0.40 + 0.30 + 0 = \mathbf{0.70}\)
Highway0.5500.45\(1.10 + 0 + 0 = \mathbf{1.10}\)

So \(a^{*} = \text{Market}\) and \(q_*(a^{*}) = 1.20\). The gap to the worst route, Hill, is \(1.20 - 0.70 = 0.50\) per delivery.

Why one try can mislead

Compare a single delivery on the best route (Market) with a single delivery on the worst (Hill). Each has three outcomes, so there are \(3 \times 3 = 9\) combinations; add the probabilities of the ones where Market pays less:

  • Market fails (0) while Hill pays anything (0.5 or 2): \(0.1 \times (0.6 + 0.2) = 0.08\).
  • Market is late (0.5) while Hill is on time (2): \(0.4 \times 0.2 = 0.08\).
  • Total: \(P(\text{Market} < \text{Hill}) = 0.08 + 0.08 = \mathbf{0.16}\).

The same counting gives \(P(\text{tie}) = 0.36\) and \(P(\text{Market} > \text{Hill}) = 0.48\); check: \(0.16 + 0.36 + 0.48 = 1\).
