Vision Transformers and VLMs

How the Transformer you already know reads images, and how it is joined to a language model. Architecture only, built one byte at a time.

·How to use these notes

These notes continue the Transformers notes (§1–58) and the Modern Transformers notes (§59–93), and section numbers continue from there. Anything already taught is cited by its section, for example §17 for the embedding table, and is not taught again. Hover a citation to preview it.

The whole point of these notes is that very little is new. A Vision Transformer is the encoder you already know, fed with a different kind of token. A vision-language model joins that encoder to a language model with parts you have also seen before. Each byte says what problem it solves, shows the equation, explains every symbol, works a small example with numbers, and checks the shapes.

These notes cover the architecture: what the parts are and how data flows through them. How these models are trained is left for later notes.

94Background: An Image as Numbers

Everything a Transformer has done so far starts from tokens: each word becomes an integer ID, then a row of the embedding table (§17). To feed it an image we first need to know what an image is to a computer. It is a grid of numbers.

Pixels and channels. A digital image is a grid of small squares called pixels. A color pixel stores three numbers: how much red, green and blue light it has. Each of these is a channel. Every value is a whole number from 0 (none of that color) to 255 (full intensity). So an image is a 3-D array, a tensor:

I∈ℝHim×Wim×C
Him: image height in pixels (number of rows) · Wim: image width in pixels (number of columns) · C: number of channels, 3 for color (RGB) and 1 for grayscale · xu,v,c: one value, at row u, column v, channel c.
In wordsAn image is Him⋅Wim⋅C numbers arranged in rows, columns and channels.

Intuition. Think of three same-sized spreadsheets stacked on top of each other: one for red, one for green, one for blue. A pixel's color is read from the same cell in all three sheets.

Worked example. A tiny 2×2 color image (a teaching choice):

Pixel (row u, column v)Looks like(R, G, B)
(1, 1) red(255, 0, 0)
(1, 2) white(255, 255, 255)
(2, 1) black(0, 0, 0)
(2, 2) blue-ish(51, 102, 204)

Stored as a tensor, the same image is three 2×2 sheets, one per channel:

Here Him=2, Wim=2 and C=3, so the image holds 2×2×3=12 numbers. For example x2,2,3=204: the blue value of the bottom-right pixel.

Scaling to [0, 1]. Networks work better with small input numbers, so each value is divided by 255:

x~u,v,c=xu,v,c255
x~u,v,c: the scaled value, between 0 and 1 · 255: the largest possible stored value.
In wordsEvery value becomes “what fraction of full intensity”.

The blue-ish pixel (51, 102, 204) becomes (0.2, 0.4, 0.8). Red becomes (1, 0, 0), white (1, 1, 1) and black (0, 0, 0):

Shape checkA standard Vision Transformer input is 224×224 pixels in color: 224×224×3 = 150,528 numbers. Keep this number in mind; the next byte asks what happens if every pixel becomes a token.
Practical noteMany models go one step further and standardize each channel as in §18: subtract a channel mean and divide by a channel standard deviation, using fixed values computed once from a large photo collection. With the commonly used ImageNet values (means 0.485, 0.456, 0.406 and standard deviations 0.229, 0.224, 0.225 for R, G, B), the red value of the blue-ish pixel becomes (0.2−0.485)/0.229 ≈ −1.24, and the whole pixel becomes about (−1.24, −0.25, 1.75). This is a preprocessing convention, not part of the architecture. Libraries also differ in axis order: some store Him×Wim×C, others C×Him×Wim. The numbers are the same, only arranged differently.
Key ideaTo a Transformer, an image is just a block of Him⋅Wim⋅C numbers. The next bytes decide how to cut that block into tokens.
