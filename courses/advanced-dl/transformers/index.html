Part I

Attention, Query/Key/Value, Heads and Position

We build the attention operation from its origin in translation models, then give it multiple heads and a sense of word order.

1From Bahdanau Attention to Self-Attention

The bottleneck that attention removed

In an encoder–decoder sequence-to-sequence model, the encoder reads the source sentence and produces one hidden state \(h_j\) for every source token \(j\). The decoder then writes the output one token at a time, keeping its own running state \(s_i\).

Early models squeezed the whole source sentence into a single fixed-size vector (the last encoder state) and handed only that to the decoder. For long sentences this vector becomes a bottleneck: everything the decoder needs must fit in one summary.

Bahdanau attention in three equations

Bahdanau attention lets the decoder look back at all encoder states and decide, at every output step \(i\), which ones matter. It takes three steps:

  1. Score every encoder state against the decoder state: \(e_{ij} = a(s_{i-1}, h_j)\). Here \(a(\cdot)\) is a small learned network (in the original paper, a one-hidden-layer network, often written \(v^\top \tanh(W_s s + W_h h)\)).
  2. Normalize the scores into weights that sum to one: \(\alpha_{ij} = \operatorname{softmax}_j(e_{ij})\).
  3. Mix: build a context vector \(c_i = \sum_j \alpha_{ij} h_j\) and give it to the decoder.
$$e_{ij} = a(s_{i-1}, h_j) \qquad \alpha_{ij} = \frac{\exp(e_{ij})}{\sum_k \exp(e_{ik})} \qquad c_i = \sum_j \alpha_{ij}\, h_j$$
\(s_{i-1}\): decoder state before step \(i\) · \(h_j\): encoder state of source token \(j\) · \(\alpha_{ij}\): how much step \(i\) reads token \(j\).

Small example: three source tokens and scores \(e = [2, 0, 1]\). Softmax gives weights \([0.665, 0.090, 0.245]\). The context vector is \(0.665\,h_1 + 0.090\,h_2 + 0.245\,h_3\), so the decoder mostly “reads” the first source token at this step. (Softmax is defined in detail in §6.3; for now read it as “turn scores into weights that sum to one”.)

Pattern to rememberEvery attention mechanism in these notes follows the same three steps: score → normalize → mix. Only the source of the scores changes.

From attention between sequences to attention within a sequence

Self-attention applies the attention idea within a single sequence. Instead of a decoder token attending to encoder states, each token can attend to other tokens in the same sequence — including itself.

Consider: “The animal didn't cross the street because it was too tired.” To interpret “it”, the model may need information about “animal”. Self-attention provides a mechanism for building that contextual relationship.

Key ideaSelf-attention does not assign equal importance to every token. Each token learns a distribution of attention weights over the sequence.

2Query and Key: What am I looking for, and what do I offer?

The Query and Key vectors provide a learned way to compare the information needs of one token with the information offered by another.

  • Query (Q) a representation of what the current token is looking for.
  • Key (K) a representation of what another token offers for matching against a query.

A useful analogy is a library search. The search request is the Query; the catalogue description used to match books to the request is the Key.

For “The cat chased the mouse”, the representation of “chased” may need to identify who performed the action and what was affected. Its Query can be compared with the Keys of “The”, “cat”, “chased” and “mouse”.

3Value: What information is contributed?

The Value vector represents the information a token contributes when it receives attention. Query–Key compatibility determines how much attention a token receives; the Value determines what information is mixed into the result.

For an illustrative example, suppose the token “chased” assigns these weights (we will derive exactly these numbers from dot-product scores in §6):

TokenIllustrative weight
The0.04
cat0.29
chased0.07
mouse0.60

The output for “chased” is a weighted combination of the Value vectors of all tokens. A token with a larger attention weight contributes more strongly to that combination.

$$\text{output}(\text{chased}) = 0.04\,V_{\text{the}} + 0.29\,V_{\text{cat}} + 0.07\,V_{\text{chased}} + 0.60\,V_{\text{mouse}}$$
Keep the roles separateQ and K determine the attention weights. V supplies the content that is combined using those weights.

4How Q, K and V are produced

The model does not normally receive Query, Key and Value vectors directly. It creates them by applying three learned linear projections to the input representations.

$$Q = X W_Q \qquad K = X W_K \qquad V = X W_V$$
\(X\): input representation (one row per token) · \(W_Q, W_K, W_V\): three learned matrices.

The projection matrices \(W_Q\), \(W_K\) and \(W_V\) are learned during training through backpropagation. They are distinct because the model benefits from learning different representations for querying, matching and contributing information.

For a single token, suppose \(X\) has shape \(1 \times 4\) and each projection matrix has shape \(4 \times 3\). Then each projected representation has shape \(1 \times 3\).

ObjectExample shapeMeaning
\(X\)1 × 4Input representation
\(W_Q, W_K, W_V\)4 × 3Learned projection matrices
\(Q, K, V\)1 × 3Projected representations

5Dot-Product Attention Scores

A Query is compared with each Key using a dot product (multiply matching components and add them up). For token \(i\) attending to token \(j\):

$$s_{ij} = q_i \cdot k_j = \sum_{c} q_{i,c}\, k_{j,c}$$

A larger score means that the learned Query and Key are more compatible. It should not automatically be interpreted as ordinary semantic similarity: the score depends on the learned representation and can also be affected by vector magnitudes.

For a small illustration, let \(q_{\text{chased}} = [1, 2]\), and let the Keys be:

TokenKeyDot product with \(q_{\text{chased}}\)
The[1, 0]1·1 + 2·0 = 1
cat[2, 1]1·2 + 2·1 = 4
chased[0, 1]1·0 + 2·1 = 2
mouse[1, 2]1·1 + 2·2 = 5

These four scores, \([1, 4, 2, 5]\), are what §6.3 will convert into attention weights. With all tokens processed together, the score matrix is obtained by matrix multiplication:

$$S = Q K^\top$$
Entry \((i, j)\) of \(QK^\top\) is row \(i\) of \(Q\) dotted with row \(j\) of \(K\) — exactly \(s_{ij}\).

If there are \(T\) tokens, \(S\) has shape \(T \times T\). Row \(i\) contains the scores for token \(i\) against every token in the sequence.

6Scaling and Softmax

6.1 Why scale the dot products?

As the Query/Key dimension \(d_k\) increases, the magnitude and variability of dot products tend to increase. Feeding very large scores directly into softmax can make the distribution overly concentrated. In saturated regions, softmax gradients can become small, making learning less effective.

The Transformer therefore divides the dot products by \(\sqrt{d_k}\) before applying softmax.

$$\text{Scaled scores} = \frac{Q K^\top}{\sqrt{d_k}}$$

6.2 Intuition for the \(\sqrt{d_k}\) factor

Background: varianceThe variance of a random quantity measures how spread out it is (the average squared distance from its mean); the standard deviation (SD) is its square root. For independent quantities, variances add: \(\operatorname{Var}(a+b)=\operatorname{Var}(a)+\operatorname{Var}(b)\). Scaling a quantity by \(c\) scales its variance by \(c^2\).

A simplified derivation assumes that Query and Key components are independent, have zero mean and unit variance. For one component, define \(z_i = q_i k_i\). Under these assumptions:

$$\mathbb{E}[z_i] = 0 \qquad \operatorname{Var}(z_i) = \mathbb{E}[q_i^2]\,\mathbb{E}[k_i^2] = 1$$

The dot product is the sum of \(d_k\) such terms. If the terms are independent, their variances add:

$$S = \sum_{i=1}^{d_k} q_i k_i \qquad \operatorname{Var}(S) = d_k \qquad \operatorname{SD}(S) = \sqrt{d_k}$$

Dividing by \(\sqrt{d_k}\) gives a scaled score with variance approximately one under the stated assumptions:

$$\operatorname{Var}\!\left(\frac{S}{\sqrt{d_k}}\right) = \frac{1}{d_k}\operatorname{Var}(S) = 1$$

Example: for \(d_k = 64\), raw scores typically have a standard deviation of 8; after scaling it is 1. Real learned Query and Key components need not satisfy the assumptions exactly, so this is a design rationale rather than a guarantee about every trained model.

6.3 Softmax turns scores into weights

$$\operatorname{softmax}(x)_i = \frac{e^{x_i}}{\sum_j e^{x_j}}$$
  • Every output is positive (an exponential is never negative).
  • The outputs sum to one across the selected row.
  • Each value lies between zero and one.
  • Larger scores get disproportionately larger weights, because the exponential amplifies differences.

Softmax is applied row-wise: each token gets its own distribution over the tokens it can attend to.

Worked example. Take the scores \([1, 4, 2, 5]\) for “chased” from the previous byte, with \(d_k = 2\) so that \(\sqrt{d_k} \approx 1.414\). Scaled scores: \([0.707, 2.828, 1.414, 3.536]\). Exponentials: \([2.03, 16.9, 4.11, 34.3]\), which add up to about 57.4. Dividing each by 57.4:

TokenRaw scoreScaled scoreWeight (softmax)
The10.7070.035 ≈ 0.04
cat42.8280.295 ≈ 0.29
chased21.4140.072 ≈ 0.07
mouse53.5360.598 ≈ 0.60

These are the weights used in the Value byte above. For contrast, softmax of the unscaled scores \([1, 4, 2, 5]\) is \([0.013, 0.256, 0.035, 0.696]\): the distribution is sharper, which is the concentration effect that scaling is designed to soften.

Practical noteSoftmax gives the same result if you subtract the same constant from every score in a row. Implementations subtract the row maximum first so that \(e^x\) never overflows.

Putting scores, scaling, softmax and Values together gives scaled dot-product attention:

$$\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_k}}\right) V$$

7Vectorizing Single-Head Self-Attention

Instead of computing attention one token at a time, the same operation can be expressed using matrix multiplication. This is both concise and efficient on modern hardware.

Suppose the input contains five tokens, each represented by a four-dimensional embedding: \(X \in \mathbb{R}^{5\times4}\). Let each projection matrix have shape \(4 \times 3\). Then:

$$Q = XW_Q,\quad K = XW_K,\quad V = XW_V \qquad Q, K, V \in \mathbb{R}^{5\times3}$$

The score matrix and attention matrix have shape \(5 \times 5\):

$$S = QK^\top \in \mathbb{R}^{5\times5} \qquad A = \operatorname{softmax}\!\left(\frac{S}{\sqrt{d_k}}\right) \in \mathbb{R}^{5\times5}$$

Finally, multiplying \(A\) by \(V\) combines information from the sequence:

$$O = AV \qquad (5\times5)(5\times3) = 5\times3$$
Shape checkThe attention matrix is \(T \times T\). It mixes information across tokens, while the final output keeps the projected feature dimension.

8Multi-Head Attention: Why use multiple heads?

A single attention head produces one attention distribution per token. Multi-head attention gives the model several independently learned attention mechanisms, allowing different heads to capture different relationships in parallel.

For example, heads may learn to focus on syntactic dependencies, long-distance relationships, coreference, or nearby context. These are possible patterns that can emerge during training — not fixed jobs assigned to particular heads.

Each head \(h\) has its own projection matrices \(W_Q^{(h)}, W_K^{(h)}, W_V^{(h)}\), each of shape \(D \times d_k\), and runs scaled dot-product attention on its own projections:

$$\text{head}_h = \operatorname{Attention}\!\left(XW_Q^{(h)},\; XW_K^{(h)},\; XW_V^{(h)}\right)$$

The head outputs are concatenated and passed through a learned output projection \(W_O\) (shape \(D \times D\)):

$$\operatorname{MultiHead}(X) = \operatorname{Concat}(\text{head}_1, \dots, \text{head}_H)\, W_O$$

For a model dimension of 512 and eight heads, a common choice is 64 dimensions per head. Concatenating eight 64-dimensional outputs returns to 512 dimensions before the output projection.

9Vectorizing Multi-Head Attention

Multi-head attention is usually implemented without writing a separate loop for every head. The projections for all heads can be computed together, then the tensor is reshaped so that the head dimension is explicit.

Let the input tensor have shape \(X \in \mathbb{R}^{B\times T\times D}\). For example, \(B = 2\), \(T = 5\), \(D = 512\) and \(H = 8\). Each head has \(d_k = D/H = 64\).

9.1 Project all heads together

The Query, Key and Value projections can each be represented by a \(512 \times 512\) matrix (the eight per-head matrices stacked side by side). Their outputs initially have shape \((2, 5, 512)\).

$$Q, K, V : (B, T, D) = (2, 5, 512)$$

9.2 Split the head dimension

Reshape the final dimension into \(H\) heads of size \(d_k\), then transpose the sequence and head axes:

$$(2, 5, 512) \;\to\; (2, 5, 8, 64) \;\to\; (2, 8, 5, 64)$$

Now each batch item contains eight independent attention sequences, each with five tokens and 64 features per token.

9.3 Compute attention in parallel

$$(2, 8, 5, 64) \times (2, 8, 64, 5) \;\to\; (2, 8, 5, 5)$$
Batched matrix multiplication: the leading axes (2, 8) are just carried along; the last two axes multiply as ordinary matrices \((5\times64)(64\times5)\).

Scale the scores by \(\sqrt{64} = 8\) and apply softmax over the final key-position axis. Multiplying the resulting attention weights by \(V\) produces:

$$(2, 8, 5, 5) \times (2, 8, 5, 64) \;\to\; (2, 8, 5, 64)$$

9.4 Merge heads and project

Transpose back to \((2, 5, 8, 64)\), reshape to \((2, 5, 512)\), and apply the output projection \(W_O\):

$$(2, 5, 8, 64) \;\to\; (2, 5, 512) \;\xrightarrow{\;W_O\;}\; (2, 5, 512)$$
Implementation connectionCommon tensor operations are Linear, reshape/view, transpose/permute, matmul and softmax. Batched matrix multiplication lets the hardware process heads together.

10Why Transformers Need Positional Information

Self-attention compares token representations, but the basic operation does not inherently know the order in which tokens appeared. Without positional information, it has no direct signal that one token came before another.

Compare “The dog chased the cat” with “The cat chased the dog”. The same words appear, but their order changes the meaning. A Transformer needs a way to represent token position.

More precisely, self-attention without positional information is permutation-equivariant: if the input token representations are permuted, the output representations are permuted in the corresponding way. The operation itself does not identify the original sequence order.

11Positional Encoding: The Basic Idea

A common approach is to add a positional vector to each token embedding before the Query, Key and Value projections:

$$X_i = E_i + P_i$$
\(E_i\): the token embedding at position \(i\) (what the token is) · \(P_i\): the positional representation for position \(i\) (where it is).

The positional vector must have the same dimension as the token embedding so that element-wise addition is possible. The resulting representation carries both token identity information and position information.

12Sinusoidal Positional Encoding

The original Transformer used fixed sinusoidal positional encodings. Each position is represented using sine and cosine waves at multiple frequencies.

$$PE(pos,\,2i) = \sin\!\left(\frac{pos}{10000^{2i/d_{model}}}\right) \qquad PE(pos,\,2i{+}1) = \cos\!\left(\frac{pos}{10000^{2i/d_{model}}}\right)$$
\(pos\): the token's position (counting from 0) · \(i\): indexes a pair of embedding dimensions · \(d_{model}\): the model dimension. The quantity \(\omega_i = 1/10000^{2i/d_{model}}\) is the angular frequency of pair \(i\).

For each dimension pair, the even dimension uses sine and the odd dimension uses cosine at the same frequency. Different dimension pairs use different frequencies.

12.1 A small example

If \(d_{model} = 4\), there are two sine/cosine pairs. Their frequencies correspond to denominators 1 and 100:

$$PE(pos) = \big[\sin(pos),\ \cos(pos),\ \sin(pos/100),\ \cos(pos/100)\big]$$

At position zero: \(PE(0) = [0, 1, 0, 1]\). At position one, approximately: \(PE(1) = [0.8415, 0.5403, 0.0100, 0.99995]\).

The first pair changes relatively quickly, while the second pair changes slowly. Together, the dimensions form a multi-frequency positional signature. (Part III uses exactly this four-dimensional encoding.)

12.2 Why use multiple frequencies?

For \(d_{model} = 8\), the four dimension pairs have angular frequencies 1, 0.1, 0.01 and 0.001. Higher-frequency components change more rapidly with position; lower-frequency components change more gradually.

  • Fast-changing components can distinguish nearby positions.
  • Slow-changing components provide information that varies over longer distances.

The combination gives the model a rich representation of position. It is best understood as a useful positional signature, not as a claim that every possible position is guaranteed to have a perfectly unique representation in finite precision.

12.3 A useful mathematical property

For one sine/cosine pair with angular frequency \(\omega\), write the positional vector as \(PE(pos) = [\sin(\omega\,pos),\ \cos(\omega\,pos)]^\top\).

Background: angle-addition identities\(\sin(a+b) = \sin a\cos b + \cos a \sin b\) and \(\cos(a+b) = \cos a\cos b - \sin a\sin b\). Set \(a = \omega\,pos\) and \(b = \omega k\): the new sine and cosine are fixed combinations of the old ones, with coefficients that depend only on \(k\).

Using these identities, the encoding at a shifted position \(pos + k\) can be obtained from the encoding at \(pos\) through a fixed rotation-like linear transformation:

$$PE(pos+k) = \begin{bmatrix}\cos(\omega k) & \sin(\omega k)\\ -\sin(\omega k) & \cos(\omega k)\end{bmatrix} PE(pos)$$

The important intuition is that a fixed offset \(k\) corresponds to a predictable transformation for each frequency. This gives sinusoidal encodings mathematical structure that can help a model learn relationships involving relative offsets. The original Transformer does not explicitly compute a relative-position matrix using this identity.

12.4 Properties and limitations

  • The encodings are fixed and deterministic; they are not learned parameters.
  • They can be evaluated at positions beyond those seen during training.
  • Being evaluable at longer positions does not guarantee that the model will generalize well to those lengths.
  • Position is added to the token representation before the Q/K/V projections.

13Other Positional Approaches

13.1 Learned absolute positional embeddings

Instead of calculating position vectors with sine and cosine, the model can learn a positional vector for each position. These vectors are stored in a trainable table:

$$P \in \mathbb{R}^{L_{max}\times D} \qquad X_i = E_i + P_i$$
\(L_{max}\): the longest sequence the model is configured for. Row \(i\) of \(P\) is the learned vector for position \(i\).

The vectors are learned through training, just like other model parameters. This approach is straightforward, but it typically requires a configured maximum sequence length and represents absolute positions rather than directly encoding the distance between two tokens. BERT and GPT-2 are examples of models using learned absolute positional embeddings.

13.2 Relative positional encoding

Relative positional methods represent how far apart two tokens are, and sometimes the direction of that distance. Rather than relying only on the absolute position of token \(i\) or \(j\), the attention calculation can include their relative offset.

$$e_{ij} = \frac{q_i^\top k_j}{\sqrt{d_k}} + b_{i-j}$$

Here, \(b_{i-j}\) is a learned bias associated with the relative offset between positions \(i\) and \(j\). This is a simplified illustration; practical relative-position methods may inject positional information into Keys and/or Values in other ways. Transformer-XL and T5 use relative-position approaches.

InterpretationA relative method can directly represent that one token is, for example, three positions before another token.

13.3 Rotary Positional Embeddings (RoPE)

RoPE introduces position by rotating Query and Key representations. It does not simply add a positional vector to the token embedding.

For a two-dimensional pair, a rotation by angle \(\theta\) is represented by:

$$R(\theta) = \begin{bmatrix}\cos\theta & -\sin\theta\\ \sin\theta & \cos\theta\end{bmatrix}$$

At position \(m\), rotate a Query pair by \(m\theta\); at position \(n\), rotate a Key pair by \(n\theta\):

$$q'_m = R(m\theta)\, q_m \qquad k'_n = R(n\theta)\, k_n$$

Their dot product becomes (using \(R(a)^\top = R(-a)\) and \(R(a)R(b) = R(a+b)\)):

$$(q'_m)^\top k'_n = q_m^\top R(m\theta)^\top R(n\theta)\, k_n = q_m^\top R\big((n-m)\theta\big)\, k_n$$

The resulting Query–Key interaction depends on the relative offset \(n - m\). This is the central intuition behind RoPE: positional information is incorporated into attention through rotations, making relative position part of the Query–Key interaction. RoPE is used in the LLaMA model family.

15Consolidated Mental Model

  1. Token embeddings represent what the tokens are.
  2. Positional information represents where the tokens occur or how they relate by position.
  3. Queries express what each token is looking for.
  4. Keys provide representations against which Queries are compared.
  5. Scaled dot products produce compatibility scores.
  6. Softmax converts scores into attention weights.
  7. Values provide the information mixed according to those weights.
  8. Multiple heads allow several learned attention patterns to operate in parallel.
  9. The output projection combines the heads into the model representation.
One-line summaryAttention determines which information to gather and how much; positional methods provide information about sequence order and distance.

16The Big Picture: What Are We Building?

Throughout Parts II and III the running task is translation: the English source sentence “I eat” should become the French target sentence “Je mange”. The original 2017 Transformer solves this with two halves that work together.

  • Encoder: reads the complete source sequence and builds a contextual vector for every source token. It does not itself produce the translation.
  • Decoder: generates the target sequence one token at a time. At each step it uses the target tokens written so far and retrieves relevant information from the encoder output.

Each half is a stack of identical layers (six encoder layers and six decoder layers in the original). The data flow, with the shape of each tensor, is:

StageWhat happensOutput shape
1Source tokens → embeddings + positions\(T_{src}\times D\)
2Encoder stack (\(N\) layers)\(M_{enc}\): \(T_{src}\times D\)
3Target prefix tokens → embeddings + positions\(T_{tgt}\times D\)
4Decoder stack (\(N\) layers); every layer also reads \(M_{enc}\)\(X_{dec}\): \(T_{tgt}\times D\)
5Linear layer + softmax over the vocabulary\(T_{tgt}\times N_{vocab}\)

The original base model uses \(D = 512\), \(H = 8\) heads, an inner feed-forward size \(d_{ff} = 2048\) and \(N = 6\) layers per stack.

Two things to notice early(1) The encoder output \(M_{enc}\) is computed once; every decoder layer attends to this same final encoder output, not to a layer-matched encoder state. (2) Every layer keeps the same shape (tokens × \(D\)) in and out, which is what makes stacking possible.

17From Text to Vectors: Tokens, IDs and the Embedding Table

A neural network cannot read text, so text is converted to numbers in three steps.

  1. Tokenize: split the text into tokens (words or word pieces). “I eat” → [“I”, “eat”].
  2. Look up IDs: each token has an integer ID in a fixed vocabulary, e.g. I → 1, eat → 2.
  3. Embed: replace each ID by a learned vector of length \(D\), taken from an embedding table.

A token ID is only an index: ID 4 is not “bigger” or “more similar” than ID 2, so it is not a useful feature. The embedding table is a learned matrix with one row per vocabulary entry:

$$E \in \mathbb{R}^{N_{vocab}\times D} \qquad \text{embedding of the token with ID } k = \text{row } k \text{ of } E$$

For a sentence with \(T\) tokens the lookup produces a \(T\times D\) matrix. The rows of \(E\) are ordinary parameters, learned by backpropagation together with the rest of the model.

Special tokens are added to the vocabulary: <BOS> (beginning of sequence), <EOS> (end of sequence) and <PAD> (padding, see §25).

Scaling and adding position

The original Transformer multiplies embeddings by \(\sqrt{D}\) before adding the positional encoding from §12:

$$X = \sqrt{D}\cdot E[\text{ids}] + PE$$

A commonly given reason is that this keeps the embedding magnitude comparable to the positional signal, whose entries lie between −1 and 1. For \(D = 512\), \(\sqrt{D}\approx 22.6\); in the miniature model of Part III, \(D = 4\) so the factor is exactly 2.

Shape checkIDs: \((T)\) → embedding lookup: \((T\times D)\) → add PE \((T\times D)\): still \((T\times D)\). From here on, “\(X\)” denotes a \(T\times D\) matrix with one row per token.

18Background: Mean, Variance and Standardization

The next block (layer normalization) needs three simple statistics of a list of numbers \(x_1, \dots, x_D\).

$$\mu = \frac{1}{D}\sum_{k=1}^{D} x_k \qquad \sigma^2 = \frac{1}{D}\sum_{k=1}^{D} (x_k-\mu)^2 \qquad \sigma = \sqrt{\sigma^2}$$
mean \(\mu\) · variance \(\sigma^2\) · standard deviation \(\sigma\).

The mean is the average; the variance is the average squared distance from the mean (so it measures spread); the standard deviation brings the spread back to the original units. Standardizing subtracts the mean and divides by the standard deviation:

$$z_k = \frac{x_k - \mu}{\sigma}$$

The standardized list always has mean 0 and variance 1, whatever the original scale.

Example. \(x = [1, 2, 3, 6]\). The mean is \(\mu = 12/4 = 3\). The deviations \(x - \mu\) are \([-2, -1, 0, 3]\); squared they are \([4, 1, 0, 9]\), so \(\sigma^2 = 14/4 = 3.5\) and \(\sigma = 1.8708\). Hence \(z = [-1.069, -0.535, 0, 1.604]\). Check: these four numbers add up to zero (mean 0), and their squares average to 1.

19Layer Normalization

In a deep network the scale of the numbers flowing through the layers can drift up or down, which makes training unstable. Layer normalization keeps every token vector on a consistent scale. It standardizes each token's \(D\) features (using the statistics of §18), then lets the model re-scale and shift the result with learned parameters:

$$\operatorname{LN}(x) = \gamma \odot \frac{x - \mu}{\sqrt{\sigma^2 + \varepsilon}} + \beta$$
  • \(\mu\) and \(\sigma^2\) are computed over the \(D\) features of this one token vector.
  • \(\varepsilon\) (for example \(10^{-5}\)) is a tiny constant that prevents division by zero.
  • \(\gamma\) (scale) and \(\beta\) (shift) are learned vectors of length \(D\), initialized to ones and zeros; \(\odot\) means element-wise multiplication.

Example. For \(x = [1, 2, 3, 6]\) the standardized vector is \([-1.069, -0.535, 0, 1.604]\) (from §18; \(\varepsilon\) changes it only in the fifth decimal). With \(\gamma = [1.5, 0.5, 1, 1]\) and \(\beta = [0, 0, 0, 0.1]\) the output is \([-1.604, -0.267, 0, 1.704]\).

20Residual Connections

A residual (or skip) connection adds a block's input to its output:

$$y = x + F(x)$$

The block \(F\) only has to learn a correction to \(x\) rather than rewrite \(x\) from scratch. Example: \(x = [1, 2]\) and \(F(x) = [0.1, -0.3]\) give \(y = [1.1, 1.7]\).

Background: the chain ruleIf \(y = f(g(x))\), then \(\frac{dy}{dx} = f'(g(x))\cdot g'(x)\): the derivative through a chain of functions is the product of the individual derivatives. Training uses this to send the error signal (the gradient) backwards through every layer.

There is a second, deeper reason. The gradient through a stack of layers is the product of each layer's derivative. If each layer's derivative is about 0.1, six plain layers multiply to \(0.1^6 = 10^{-6}\) and the gradient vanishes. With a residual connection the derivative of each layer is \(1 + F'(x)\), so six layers give about \((1.1)^6 \approx 1.77\). The “+1” is a direct path for gradients to travel through the whole stack.

Requirement\(x\) and \(F(x)\) must have the same shape so that they can be added. This is why the model dimension \(D\) is kept constant through every layer.

21Add & Norm: Wrapping a Sublayer

Every sublayer in the Transformer (attention or feed-forward) is wrapped the same way: apply the sublayer, add the input back (§20), then normalize (§19).

$$Y = \operatorname{LayerNorm}\big(X + \operatorname{Sublayer}(X)\big)$$

This arrangement is called Post-LN and is what the original paper uses. Many later models use Pre-LN instead, \(Y = X + \operatorname{Sublayer}(\operatorname{LayerNorm}(X))\), which is often reported to train more stably for very deep stacks; the building blocks are the same, only their order changes.

Where it is usedTwo Add & Norm wrappers per encoder layer and three per decoder layer. Shapes never change: \(T\times D\) in, \(T\times D\) out.

22Background: ReLU and Why We Need a Nonlinearity

ReLU (rectified linear unit) is applied element by element: it keeps positive numbers and replaces negative numbers by zero.

$$\operatorname{ReLU}(x) = \max(0, x) \qquad \operatorname{ReLU}([1, -2, 0.5, 0]) = [1, 0, 0.5, 0]$$

Why is it needed? Two matrix multiplications in a row collapse into one: \((xW_1)W_2 = x(W_1W_2)\). Without a nonlinearity between them, a two-layer network would be no more expressive than a single matrix. Putting ReLU in between breaks this collapse and lets the network represent far more complicated functions.

23The Position-wise Feed-Forward Network

Attention mixes information between tokens. The feed-forward network (FFN) then transforms the features within each token. It is two linear layers with a ReLU between them:

$$\operatorname{FFN}(x) = \operatorname{ReLU}(xW_1 + b_1)\,W_2 + b_2$$
  • \(W_1\) has shape \(D\times d_{ff}\) and expands each token vector; \(W_2\) has shape \(d_{ff}\times D\) and projects it back. The original uses \(D = 512\) and \(d_{ff} = 2048\).
  • “Position-wise” means that the same \(W_1, W_2\) are applied to every token row independently. No information moves between tokens inside the FFN.
  • Parameter count (base model): FFN ≈ 2·512·2048 ≈ 2.1 million; the four attention matrices \(W_Q, W_K, W_V, W_O\) ≈ 4·512² ≈ 1.05 million. About two thirds of each layer's parameters sit in the FFN.

Toy example used in Part III. Let \(D = 4\), \(d_{ff} = 8\), \(W_1 = [I \mid -I]\) (the identity placed next to its negative) and \(W_2 = \begin{bmatrix} I \\ I\end{bmatrix}\) (the identity stacked on itself), with zero biases. For \(x = [1, -2, 0.5, 0]\): \(xW_1 = [1, -2, 0.5, 0, -1, 2, -0.5, 0]\); ReLU gives \([1, 0, 0.5, 0, 0, 2, 0, 0]\); multiplying by \(W_2\) adds the two halves: \([1, 2, 0.5, 0]\). This tiny FFN computes \(|x|\) (the absolute value of each entry), a genuinely nonlinear function that is easy to check by hand.

Shape check\(T\times D \to T\times d_{ff} \to T\times D\).

24The Encoder Layer: Assembling the Blocks

An encoder layer is exactly two Add & Norm blocks (§21):

$$X' = \operatorname{LayerNorm}\big(X + \operatorname{MultiHeadAttention}(X, X, X)\big)$$ $$Y = \operatorname{LayerNorm}\big(X' + \operatorname{FFN}(X')\big)$$

In the attention sublayer, Q, K and V are all projected from the same \(X\), so it is self-attention (§9). There is no causal mask: every source token may look at every other source token, in both directions, which is what lets the encoder build rich context.

Because \(X\) and \(Y\) have the same shape, the output of layer \(\ell\) is simply the input of layer \(\ell + 1\). The output of the last layer is the encoder output \(M_{enc}\). For the source “The cat is sleeping” (\(T_{src} = 4\)) with \(D = 512\), \(M_{enc}\) is \(4\times512\): one contextual vector per source token. It is not a translation; it is a representation that the decoder will query.

25Padding Masks

Sentences in a batch have different lengths, so shorter ones are padded with <PAD> tokens to a common length. Padded positions carry no information and must not receive attention.

We prevent attention to padding by adding \(-\infty\) to the attention score of every padded key position before the softmax.

Background: \(e^{-\infty}\)As \(x\) becomes more and more negative, \(e^{x}\) approaches 0; we write \(e^{-\infty} = 0\). So in softmax, an entry of \(-\infty\) contributes exactly 0 to the numerator and to the sum, and the other weights still sum to one.

Example. A query's scores over three key positions are \([2, 1, \text{PAD}]\). After masking they are \([2, 1, -\infty]\) and softmax gives \([0.731, 0.269, 0]\): identical to a softmax over only the two real positions. The mask is simply added to the scores:

$$S_{masked} = \frac{QK^\top}{\sqrt{d_k}} + \text{Mask}_{pad} \qquad \text{Mask}_{pad}[j] = \begin{cases}0 & \text{real key}\\ -\infty & \text{padded key}\end{cases}$$

Padding masks are used in the encoder's self-attention and on the source keys in cross-attention (§30). Padded target positions are also ignored when computing the loss (§34). The Part III example uses sentences of equal length, so no padding appears there.

26Autoregressive Generation and the Chain Rule

The decoder produces the target sentence one token at a time, and each new token depends on the tokens before it. This is called autoregressive generation.

Background: the chain rule of probability\(P(A, B) = P(A)\cdot P(B \mid A)\): the probability of two things both happening is the probability of the first times the probability of the second given the first. Applying it repeatedly splits any sequence into one factor per element.

Extended to a sequence \(y = (y_1, \dots, y_n)\) given the source \(x\):

$$P(y \mid x) = \prod_{t} P(y_t \mid y_1, \dots, y_{t-1}, x)$$

For the target “Je mange” followed by the end token:

$$P(\text{Je mange}\ \langle\text{EOS}\rangle \mid x) = P(\text{Je}\mid x)\cdot P(\text{mange}\mid \text{Je}, x)\cdot P(\langle\text{EOS}\rangle\mid \text{Je mange}, x)$$

Each factor is a classification over the whole vocabulary: “given everything so far, which token comes next?” The end token matters because it is how the model learns when to stop. Training adjusts the parameters to make the probability of the true target sequence as large as possible (see §34).

27Teacher Forcing and the Shifted Target

During training the correct target sentence is known. The decoder is trained on the chain-rule factors of §26 by being fed the true previous tokens, not its own earlier predictions. This is teacher forcing.

Concretely, the target is used twice: shifted right with <BOS> in front as the decoder input, and followed by <EOS> as the labels.

28The Causal Mask

If all three decoder positions are processed together, position 1 could attend to position 2, whose input is “Je”, which is exactly position 1's label. The model would simply copy the answer. We must forbid position \(i\) from attending to any position \(j > i\). Using the same \(-\infty\) trick as for padding (§25), we add a mask matrix before the softmax:

$$S_{masked} = \frac{QK^\top}{\sqrt{d_k}} + C \qquad C_{ij} = \begin{cases}0 & j \le i\\ -\infty & j > i\end{cases}$$

Rows are query positions and columns are key positions. The allowed entries form a lower triangle; the diagonal is allowed because a position may use its own representation.

Order mattersThe mask is added before softmax. Zeroing weights after softmax would leave rows that no longer sum to one.

29Why Training Is Parallel but Generation Is Sequential

Thanks to teacher forcing (§27) and the causal mask (§28), a training pass computes all target positions at once: every position sees only its allowed past, and all the true tokens are already known. Parallel computation does not mean the model may see the future; the mask guarantees it cannot.

At inference there is no ground truth. The token at position \(t + 1\) is not known until the model has chosen the token at position \(t\), so generation must run one step at a time (§35). The encoder is parallel in both phases, because the whole source is known.

30Cross-Attention: Connecting the Decoder to the Encoder

Cross-attention is how the decoder reads the source sentence. It is ordinary scaled dot-product attention (§6) with one change: the three projections come from two different sequences.

$$Q = X_{dec}W_Q \qquad K = M_{enc}W_K \qquad V = M_{enc}W_V$$ $$\operatorname{CrossAttention} = \operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V$$
  • Query comes from the decoder it says what the current target position is looking for, given the target text written so far.
  • Key comes from the encoder it describes what each source position can offer for matching.
  • Value comes from the encoder it is the source information that is retrieved and mixed.

In the library analogy of Part I: the decoder asks a question, the encoder's Keys decide which source positions answer it, and the encoder's Values provide the answer text. Q is decoder-derived because what to look for depends on the current generation state; K and V are encoder-derived because the information being retrieved lives in the source.

There is no causal mask over source positions (the entire source is available), but a source padding mask (§25) is applied if the batch contains padding.

Rectangular, not squareThe score matrix has one row per target position and one column per source position: \(T_{tgt}\times T_{src}\). The output has one row per target position, so cross-attention changes what each target token knows but never the number of target rows.

33From Decoder Output to Vocabulary Probabilities

Each row of the final decoder output is a \(D\)-dimensional vector. A learned linear layer converts it into one score, called a logit, for every entry in the vocabulary. Softmax (§6) then turns the logits of each row into probabilities.

$$Z = X_{dec}W_{vocab} + b \qquad P_t = \operatorname{softmax}(Z_t)$$

Shapes: \(X_{dec}\) is \(T_{tgt}\times D\), \(W_{vocab}\) is \(D\times N_{vocab}\), so \(Z\) and \(P\) are \(T_{tgt}\times N_{vocab}\). Row \(t\) holds the probability of each vocabulary token being the next token at position \(t\). Softmax is applied across the vocabulary, one row at a time. Real vocabularies have tens of thousands of entries (for example 32,000), so \(Z\) is much wider than \(X_{dec}\). The original paper also ties \(W_{vocab}\) to the embedding table (the same matrix, transposed) to save parameters.

35Inference: The Generation Loop

At inference there is no target sentence. The model builds it step by step:

  1. Run the encoder once on the source to get \(M_{enc}\).
  2. Start the target prefix with <BOS>.
  3. Run the decoder on the current prefix and take the probability distribution of the last position only.
  4. Choose the next token from that distribution: greedy decoding takes the highest-probability token; sampling draws randomly in proportion to the probabilities; beam search keeps several candidate prefixes.
  5. Append the chosen token to the prefix and repeat from step 3, until <EOS> is produced or a maximum length is reached.
Cost warningA naive implementation re-runs the whole decoder on the entire growing prefix at every step. The next three bytes show why most of that work is redundant and how to remove it.

36Why a KV Cache? Counting the Wasted Work

Key observation: because of the causal mask, an earlier position never looks at later positions. So when a new token is appended, the hidden states, Keys and Values of all earlier positions do not change. Recomputing them is pure waste.

Count the work. To generate \(T\) tokens without a cache, step \(t\) recomputes the projections for all \(t\) positions in the prefix: \(1 + 2 + \dots + T = T(T+1)/2\) position-computations. With a cache, each step processes only the one new position: \(T\) in total.

37The Self-Attention KV Cache: What Is Stored and Why

For the newly processed token representation \(x_t\), compute its three projections:

$$q_t = x_tW_Q \qquad k_t = x_tW_K \qquad v_t = x_tW_V$$

Append \(k_t\) and \(v_t\) to the cache, then let the new Query attend to everything cached:

$$o_t = \operatorname{softmax}\!\left(\frac{q_t K_{cache}^\top}{\sqrt{d_k}}\right) V_{cache}$$

The cache stores Keys and Values, not Queries. A past Query was only needed to compute that past token's own output, which is already done. Future tokens need to compare their new Queries against historical Keys and combine historical Values; they never need historical Queries.

No causal mask is needed at the new step: the new token is the last position, so every cached position is already in its allowed past. Each decoder layer keeps its own cache (its Keys and Values come from that layer's inputs), and within a layer the cache is kept per head. The cache grows by one position per generated token.

41The Complete Forward Pass

Encoder path (identical in training and inference)

  1. Tokenize the source; look up embeddings, scale by \(\sqrt{D}\) and add positions (§17).
  2. In each encoder layer: self-attention then FFN, each wrapped in Add & Norm (§24).
  3. Return the encoder output \(M_{enc}\).

Decoder path

  1. Embed the shifted-right target (training, §27) or the generated prefix (inference); scale and add positions.
  2. In each decoder layer: masked self-attention, then cross-attention to \(M_{enc}\), then FFN, each wrapped in Add & Norm (§32).
  3. Project the final decoder states to vocabulary logits and apply softmax (§33).

Training: all shifted target positions are computed in parallel under the causal mask; the cross-entropy losses are averaged (§34); gradients update the parameters once per batch.

Inference: generate one token at a time (§35). With KV caches (§37), each step projects only the new token and attends to stored history.

42Consolidated Mental Model of the Complete Transformer

  1. Embeddings plus positions turn tokens into vectors that know what they are and where they are.
  2. Attention moves information between tokens; the FFN transforms each token on its own.
  3. Residual connections keep information and gradients flowing; layer normalization keeps scales stable.
  4. The encoder reads the whole source with no mask and produces \(M_{enc}\).
  5. The decoder writes the target autoregressively: masked self-attention for the past, cross-attention for the source, FFN for processing.
  6. A linear layer and softmax turn the final decoder rows into next-token probabilities; cross-entropy measures how well the true token scored.
  7. Training is parallel because of teacher forcing and the causal mask; inference is sequential, and KV caches remove the redundant recomputation.
One-line summaryThe encoder understands the source once; the decoder repeatedly asks “what comes next?” by combining what it has written with what it retrieves from the source.

A Complete Numerical Walkthrough of a Miniature Transformer

This worked example follows the source sentence “I eat” through one encoder layer and one decoder layer, then produces vocabulary probabilities, a loss and a cached inference step. Every number was computed by running the stated equations, and every stage refers back to the byte that introduced it. The weights are tiny and hand-chosen so that the arithmetic is checkable; the mechanisms are those of the full encoder–decoder Transformer.

55Stage 12 — Inference with Two KV Caches

At inference the decoder processes one token per step (§35). To check that caching is exact, assume the model has produced <BOS>, then Je, and now processes the second step. Its input row is the same \(X_{tgt}\) row 2 as in training, so we can compare directly with Stage 6.

Self-attention cache. After step 1 the cache holds the Key and Value of <BOS>. At step 2 we project only the new token: \(q_2 = x_2W_Q\), \(k_2 = x_2W_K\), \(v_2 = x_2W_V\), and append \(k_2, v_2\).

Scores: \(q_2K_{cache}^\top/2 = [1.456, 2.2088]\) (shape \(1\times2\)). No causal mask is needed because the new token is last. Softmax gives \([0.3202, 0.6798]\). Output: \([1.6875, 0.2124, 1, 0.3664]\) (shape \(1\times4\)).

Exactness checkThe weights \([0.3202, 0.6798]\) equal row 2 of \(A_{masked}\) in Stage 6 (the third entry there is 0 by the mask), and the output \([1.6875, 0.2124, 1, 0.3664]\) equals row 2 of \(O_{self}\). The cache gives exactly the same answer while projecting one token instead of two.

Cross-attention cache. \(K_{cross} = M_{enc}W_K\) and \(V_{cross} = M_{enc}W_V\) depend only on the encoder output, which is fixed for the whole sentence. They are computed once (the matrices in Stage 8) and reused unchanged at steps 1, 2 and 3. The new decoder Query changes at every step; the source Keys and Values do not.

For one head and two cached positions the shapes are: new Query \(1\times4\), cached K and V \(2\times4\), scores \(1\times2\), output \(1\times4\). In a model with several layers each decoder layer keeps its own pair of caches.

58What This Tiny Example Does and Does Not Demonstrate

It demonstrates the data flow and arithmetic of one encoder layer and one decoder layer: embedding lookup and scaling, sinusoidal positions, scaled dot-product attention, the causal mask, residual connections, LayerNorm, the FFN, cross-attention, vocabulary projection, softmax, cross-entropy and an exact KV-cache step.

It deliberately simplifies: one head instead of several, four-dimensional vectors, identity or hand-chosen weights (shared across the three attention blocks), no biases, no dropout, no padding, and a loss computed on an untrained model. A production Transformer uses larger dimensions, multiple heads, many stacked layers, trained parameters, batching, and further implementation details.
