Part IV

The Transformer Since 2017

The 2017 architecture survived almost unchanged at the level of ideas: attention, residuals, normalization and an FFN are still the whole story. What changed is which pieces are kept, how they are ordered and normalized, how position is represented, and how attention is made affordable at long lengths. This Part goes through those changes one at a time.

60Background: Subword Tokens and Byte-Pair Encoding

§17 assumed that a fixed vocabulary already exists and simply turns tokens into IDs. Pretraining on raw text from the web forces the question: what should the tokens be?

  • Whole words are a bad fit for an open-ended text stream: there are too many of them, and any new word (a name, a typo, “unfriendliest”) has no ID.
  • Single characters never run out, but sequences become very long, and attention cost grows with length (as we will count in §75).

Subword tokenization sits between the two. Frequent words become single tokens, and rare words are built from frequent pieces. Byte-Pair Encoding (BPE) learns those pieces from a corpus with one simple rule, repeated:

repeat k times:(a,b)=arg maxadjacent pairscount⁡(ab),replace every ab by the new symbol ab
k: number of merges, chosen in advance (it sets the vocabulary size) · count⁡(ab): how often symbol a is directly followed by symbol b, weighted by word frequency.
In wordsStart from single characters. Find the pair of neighbours that occurs most often and glue it into one new token. Do that again, as many times as you want vocabulary entries.

Worked example. A corpus of 16 words: “low” ×5, “lower” ×2, “newest” ×6, “widest” ×3. Each word ends with an end-of-word marker _, so that “est” at the end of a word can be told apart from “est” inside one. That gives 11 starting symbols and 95 symbols in total.

MergePair gluedCountWhy this count
1e + s → es9“newest” (6) + “widest” (3)
2es + t → est9the same 9 words
3est + _ → est_9“est” always ends those words
4l + o → lo7“low” (5) + “lower” (2)
5lo + w → low7the same 7 words
6n + e → ne6“newest” (6); ties with “e + w”, and the first pair found wins

After 6 merges the vocabulary has 17 symbols and the corpus is 48 symbols long instead of 95. A word never seen in training still gets tokens: “lowest” → low · est_, built from two learned pieces. The rarer “newer” falls back to smaller pieces: ne · w · e · r · _.

Byte-level BPEGPT-2 runs BPE on the bytes of UTF-8 text instead of on characters. The 256 possible byte values are the starting symbols, so every possible string can be tokenized and no “unknown” token is needed. Vocabulary sizes are design choices: GPT-2 has 50,257 entries and Llama 3 has 128,256.
Shape checkThe vocabulary size Nvocab fixes two tables of §17 and §33: the embedding table E (Nvocab×D) and the output projection (D×Nvocab). A larger vocabulary makes sequences shorter but these tables bigger. §71 puts a number on that trade-off.

61Self-Supervised Pretraining

The model of Part III learned from pairs: an English sentence and its French translation. Labelled pairs are expensive, so there are few of them. Unlabelled text is plentiful. Self-supervised learning makes labels out of the text itself: hide part of a sentence, and train the model to fill it back in. The hidden part is the label, so no human has to write one.

ℒpretrain=−1|𝒫|∑t∈𝒫log⁡P(xt∣the visible context)
xt: the true token at position t · 𝒫: the set of positions the model must predict, |𝒫| how many there are · “the visible context”: whatever the objective allows the model to see.
In wordsAverage, over the positions you chose to hide, the cross-entropy of §34: how surprised the model is by the true token, given what it is allowed to see.

The objectives of the next three bytes differ only in which positions are in 𝒫 and what context is visible. Everything else (the embedding, the layers, the softmax over the vocabulary, the loss) is what you already know.

After pretraining, the model is fine-tuned: it is trained further, for a short time, on a small labelled dataset for the task you actually care about. The representations learned in pretraining make that second step need far less labelled data. The exact amount depends on the task.

62Encoder-Only Models: BERT and Masked Language Modelling

Take only the encoder of §24: self-attention with no causal mask, so every token sees every other token. Such a model can't generate text left to right, but it can read a whole sentence in both directions at once. The masked language modelling (MLM) objective fits that:

  1. Choose 15% of the positions at random. These form 𝒫.
  2. Of the chosen positions, replace 80% by a special [MASK] token, 10% by a random token, and leave 10% unchanged.
  3. Run the encoder and predict the original token at every chosen position, using the loss of §61.

Why the 80/10/10 split? [MASK] never appears in real downstream text. If the model only ever saw [MASK] at prediction positions, it could learn “only think hard where you see [MASK]”. The random and unchanged cases force it to build a good representation of every token. The percentages are BERT's design choices, not something that was derived.

Worked example. With T=20 tokens, 0.15×20=3 positions are chosen. On average 2.4000000000000004 of them become [MASK], 0.3 become random and 0.3 stay unchanged. Suppose the model gives the true tokens probabilities 0.6, 0.25 and 0.1:

ℒ=13(−log⁡0.6−log⁡0.25−log⁡0.1)=13(0.5108+1.3863+2.3026)=1.3999
In wordsOnly the three chosen positions contribute to the loss; the other 17 positions are read but give no training signal.

How BERT is used. A special [CLS] token is put first. After fine-tuning, its final vector feeds a small classifier (for sentiment, topic, and so on), while the other tokens' vectors are used for tagging or for finding answer spans. Encoder-only models are still common wherever a representation of a text is needed rather than new text, for example sentence embeddings for search.

A detail that did not lastBERT also used a second objective, next-sentence prediction. Later work (RoBERTa, 2019) reported that removing it and training longer on more data worked at least as well, so most successors dropped it.
Shape checkInput T×D → encoder → T×D → vocabulary projection on the chosen rows only: |𝒫|×Nvocab logits.

63Decoder-Only Models: GPT and Next-Token Pretraining

Now take only the decoder of §32, and delete the cross-attention sublayer, because there is no encoder to attend to. Each layer is left with two sublayers: causal self-attention (§28) and the FFN. The objective is the chain rule of §26 applied to raw text: predict every token from the tokens before it.

ℒCLM=−1T−1∑t=2Tlog⁡P(xt∣x1,…,xt−1)
x1,…,xt−1: the prefix, which is all the causal mask allows position t−1 to see · the sum starts at t=2 because the first token has nothing before it. (In practice a <BOS> token is often put first so that x1 can be predicted too.)
In wordsShift the text by one (teacher forcing, §27) and score the true next token at every position, all in parallel under the causal mask.

Every position is a label. For the same 20-token sentence, MLM learns from 3 positions while causal LM learns from 19, which is 6.33 times as many training signals per sequence. (A masked-token prediction uses context from both sides and is a different task, so this is a count of signals, not a claim about which objective learns more per token.)

Generation is built in. The pretraining task is exactly the generation loop of §35, so a pretrained decoder can write text with no extra parts, and the KV cache of §37 applies unchanged. GPT-3 (2020) showed a further effect: given a few examples in the prompt, a large enough model can carry out a new task without any weight updates. This is called in-context learning. How well it works depends strongly on scale, which is Part V's topic.

Shape checkTokens T → T×D → L decoder layers (2 sublayers each) → T×Nvocab logits, one next-token distribution per position.

64Encoder–Decoder Revisited: T5 and Span Corruption

The full encoder–decoder of Part II is still a natural fit when there is a clear input and a separate output. T5 (2019) pretrains it with span corruption: delete short runs of tokens from the input, mark each hole with a sentinel token, and make the decoder generate the deleted runs.

Tokens
Originalthe cat sat on the warm mat today
Encoder inputthe cat <X> the warm <Y> today
Decoder target<X> sat on <Y> mat <Z>

The encoder reads the corrupted sentence with full bidirectional attention. The decoder generates only the missing pieces, each introduced by its sentinel, with a final sentinel to stop. This makes the target much shorter than the whole sentence. T5's defaults were to corrupt about 15% of tokens in spans of average length 3. T5 also casts every task as text to text: the input “translate English to German: …” produces German text, and a classification task outputs its label as a word.

Shape checkEncoder: Tsrc×D (the corrupted input). Decoder: Ttgt×D, where Ttgt is just the sentinels plus the missing tokens (here 6), not the full sentence. Cross-attention scores: Ttgt×Tsrc, as in §31.

Why did decoder-only win for large models? No single experiment settles this, but the reasons usually given are:

  1. One objective that matches use. Pretraining is the same task as generation, so nothing has to change between pretraining and use.
  2. Every token is a label (§63), so each sequence gives many training signals.
  3. Any task can be phrased as a prompt plus a continuation, including classification and translation, and in-context learning lets one model do many tasks.
  4. Simplicity at scale. There is one stack, one mask and one cache, and the engineering effort (FlashAttention, KV-cache tricks, parallelism) can all go into that one design.
HedgeThis is the common view, not a theorem. Encoder–decoder models stay competitive on tasks with a clear input→output structure. From here on, Part IV follows the decoder-only block because it is the one that nearly every recent large model is built on.

66Pre-LN and the Residual Stream

§21 introduced two orders for the same three pieces. The original paper used Post-LN, Y=LN⁡(X+Sublayer⁡(X)). Nearly every large model since GPT-2 uses Pre-LN:

Xl+1=Xl+Sublayerl⁡(Norm⁡(Xl))
Xl: the T×D matrix entering sublayer l · Norm⁡: LayerNorm, or the RMSNorm of §67 · Sublayerl⁡: attention or FFN.
In wordsNormalize a copy of the input, let the sublayer compute something from it, and add the result back to the untouched input.

Unroll it. Apply that rule L times, starting from the embeddings X0:

XL=X0+∑l=0L−1Sublayerl⁡(Norm⁡(Xl))
In wordsThe final representation is the input plus the sum of what every sublayer wrote. Nothing ever overwrites the input; sublayers only add to it.

This running sum is called the residual stream. Each sublayer reads the stream through a normalization and writes a correction back into it.

Example. Take X0=[1,0] and three sublayers that write [0.5,0.5], [−0.2,0.4] and [0.1,−0.3]. Then X3=[1+0.5−0.2+0.1,0+0.5+0.4−0.3]=[1.4,0.6]. The input is still visibly “inside” the output.

Why this trains more stably. By the chain rule (§20), the derivative of XL with respect to X0 contains the identity term from the first X0 in the sum. The gradient therefore always has a direct, unscaled path back to the bottom layer, however deep the stack. In Post-LN, every path back passes through every LayerNorm. Xiong et al. (2020) analysed this and reported that Post-LN needs a careful learning-rate warm-up to avoid diverging early in training, while Pre-LN trains well with much less of it.

One extra piece is now requiredNothing normalizes the stream itself, so its scale can grow with depth. Pre-LN models therefore apply one final normalization after the last layer, before the vocabulary projection: Z=Norm⁡(XL)Wvocab. The walkthrough uses it in §90.
Trade-offPre-LN is the common choice, not a free win. Some studies report that a well-tuned Post-LN can reach slightly better final quality, and variants that normalize in both places exist. The reason Pre-LN is the default is that it is reliable at large depth.
Shape checkEvery term in the sum is T×D; that is why every sublayer must return exactly D features, as §20 required.

67RMSNorm: Normalizing Without Centering

LayerNorm (§19) does two things to each token vector: it re-centers it (subtracts the mean μ) and re-scales it (divides by the standard deviation). RMSNorm (Zhang and Sennrich, 2019) keeps only the re-scaling:

RMSNorm⁡(x)=γ⊙xRMS⁡(x),RMS⁡(x)=1D∑k=1Dxk2+ε
x: one token's vector of D features · RMS⁡(x): the root mean square; square every feature, take the mean, take the square root · ε: the small constant of §19 · γ: learned gain of length D, initialized to ones. There is no shift β and no mean.
In wordsDivide the vector by its typical size, so that its root mean square becomes 1, then let the model stretch each feature with γ.

Why drop the mean? The authors' hypothesis was that LayerNorm's benefit comes mainly from controlling the scale of the activations, and much less from centering them. Removing the mean saves one reduction over the features in each normalization. They reported similar accuracy with less compute, and RMSNorm became the default in LLaMA and most later models. The speed-up depends on the hardware and the implementation.

68Background: The Sigmoid and Gating

The next two bytes need one more function. The sigmoid (logistic) function squashes any real number into the interval (0,1):

sigmoid⁡(z)=11+e−z
z: any real number · e−z is large for very negative z (output near 0) and tiny for very positive z (output near 1).
In wordsA smooth on/off switch: very negative means “off” (0), very positive means “on” (1), and z=0 is exactly halfway.

Values: sigmoid⁡(−2)=0.1192, sigmoid⁡(0)=0.5, sigmoid⁡(2)=0.8808. Note the symmetry sigmoid⁡(−z)=1−sigmoid⁡(z): indeed 0.1192 + 0.8808 = 1.

Tied embeddings. The output projection of §33 maps D features to Nvocab logits, and the embedding table maps IDs to D features. Tying them reuses one matrix for both jobs:

Z=Norm⁡(XL)E⊤
E: the Nvocab×D embedding table of §17 · E⊤: its transpose, D×Nvocab · Z: T×Nvocab logits.
In wordsThe logit of each vocabulary word is the dot product of the final hidden vector with that word's own embedding: “how much does my output look like this word?”

The saving is large when the vocabulary is big and the model is small. With Nvocab=128,256 and D=2,048, one table has 262,668,288 parameters (262.7 million). That is about 21% of a 1.24-billion-parameter model such as Llama 3.2 1B, which does tie its embeddings. Larger models such as Llama 3 8B keep two separate tables, so tying is a design choice. The walkthrough ties them (§90).

72RoPE Across All Frequencies

§13.3 showed RoPE for a single pair of numbers: rotate the Query at position i by angle iθ, rotate the Key at position j by jθ, and their dot product then depends only on the offset j−i. A real head has dk numbers (for example 128), not 2. RoPE splits them into dk/2 pairs and rotates each pair at its own speed:

73ALiBi: Position as a Distance Penalty

§13.2 added a learned bias bi−j to each score. ALiBi (Attention with Linear Biases; Press et al., 2021) uses a fixed bias with no parameters at all: the further back a Key is, the more its score is lowered, in a straight line.

eij=qi⊤kjdk−λh(i−j),j≤i
i: Query position · j: Key position, never later than i because of the causal mask · i−j≥0: how far back the Key is · λh>0: a fixed slope, different for each head h.
In wordsEvery step back in the text costs head h a penalty of λh on the score, before the softmax.

Different heads, different reach. The slopes form a geometric sequence. For H=8 heads they are 1/2, 1/4, 1/8, 1/16, 1/32, 1/64, 1/128, 1/256. 74Extending the Context Window

A model trained on sequences of Ltrain=4,096 tokens has only ever seen RoPE angles pθr with p<Ltrain. Its fast pairs have wrapped around the circle many times, so every angle is familiar. Its slow pairs have not completed a single turn, so a position past Ltrain gives them angles the model has never seen, and quality usually collapses. Two simple fixes, and a refinement, change the angles so that a longer sequence Lnew=s⋅Ltrain stays inside the familiar range.

1 · Position Interpolation (PI) (Chen et al., 2023) squeezes the positions:

p′=ps,s=LnewLtrain
In wordsPretend the text is s times shorter: a 16,384-token sequence gets the angles of a 4,096-token one.

With s=4, position 10,000 is treated as position 2,500. Every angle is now one the model has seen. The cost is that the fast pairs, which tell neighbouring tokens apart, are slowed down by 4 as well, so neighbours become harder to distinguish. A short fine-tuning on long texts is then used to adapt.

2 · NTK-aware scaling changes the base instead of the positions, so that the fast pairs are left alone and the slow pairs are slowed the most:

base′=base⋅sdk/(dk−2)
In wordsRaise the base just enough that the slowest pair turns exactly s times more slowly, while the fastest pair is unchanged.

Check it. The new speed of pair r is θ′r=(base′)−2r/dk=θr⋅s−2r/(dk−2). For r=0 the factor is s0=1, so the fastest pair is untouched. For the last pair, r=dk/2−1, the factor is s−1, which is exactly PI's slow-down. For dk=128 and s=4: base′=10000⋅41.0159=40,890, and the middle pair (r=32) is slowed by 2.022, between the two extremes.

3 · YaRN (Peng et al., 2023) refines both ideas. Pairs whose wavelength is short compared with Ltrain are left unchanged, pairs with long wavelengths are interpolated as in PI, and a ramp blends the two in between. It also sharpens the attention slightly, because spreading attention over many more tokens tends to make the weights flatter. Following the YaRN authors' fitted rule, Queries and Keys are both scaled by 0.1ln⁡s+1=1.1386 for s=4.

HedgeAll three methods are usually followed by some fine-tuning on longer texts. Published models combine them in their own ways; for example, Llama 3.1 reached a 128K context with a frequency-dependent RoPE rescaling plus continued training. Being able to process a long input is not the same as using all of it well, so long-context quality has to be measured separately.
Shape checkOnly the angles change. Q, K and all weights keep their shapes, and the attention matrix becomes Lnew×Lnew. The next bytes deal with that cost.

75The Cost of Attention Grows as T²

§74 made long inputs possible in principle. In practice, attention compares every Query with every Key, so its work and memory grow with the square of the length. This byte counts that cost, because the next six bytes are all ways of reducing it.

Background: counting FLOPsA FLOP is one floating-point multiply or add. Multiplying an a×b matrix by a b×c matrix computes a⋅c dot products of length b, and each needs b multiplies and about b adds. That is about 2abc FLOPs in total. Example: (2×3)(3×4) costs about 2⋅2⋅3⋅4=48 FLOPs.

In wordsPer head, both matrix products cost about two times length squared times head size, and the score and weight matrices each hold length-squared numbers.

76Multi-Query and Grouped-Query Attention

During generation, every new token reads the whole KV cache of §37. §38 gave its size as 2⋅layers⋅B⋅H⋅T⋅dk⋅bytes, which is proportional to the number of heads H, because every head stores its own Keys and Values. Grouped-Query Attention (GQA) (Ainslie et al., 2023) keeps H Query heads but only Hkv Key/Value heads, and lets each group of Query heads share one K/V head:

G=HHkv,Query head h uses K/V head ⌈hG⌉,h=1,…,H
H: Query heads · Hkv: Key/Value heads, a divisor of H · G: group size, the number of Query heads per K/V head · ⌈⋅⌉: round up.
In wordsSeveral Query heads ask different questions of the same shared Keys and Values.

Two special cases have their own names. Hkv=H is ordinary multi-head attention (MHA, §8). Hkv=1 is Multi-Query Attention (MQA; Shazeer, 2019), where all heads share a single K and V. Example: H=4, Hkv=2 gives G=2 and the map (Query head → K/V head) 1→1, 2→1, 3→2, 4→2.

KV cache=2⋅layers⋅B⋅Hkv⋅T⋅dk⋅bytes
In wordsThe same formula as §38, with the number of K/V heads Hkv in place of H. The cache is G times smaller.

Worked example (a Llama-2-70B-like configuration: 80 layers, H=64, Hkv=8, dk=128, T=4096, B=1, 2 bytes per number):

77Background: Fast and Slow GPU Memory

To see why storing the T×T matrix is costly (not just large), you need one fact about GPUs: there are two kinds of memory, and they differ enormously in speed.

MemorySizeBandwidthHolds
HBM (high-bandwidth memory, the “GPU memory”)40–80 GB≈ 1.5–2.0 TB/sweights, activations, KV cache, and in standard attention S and A
SRAM (on-chip, beside the compute units)192 KB per streaming multiprocessor, ≈ 20 MB in total≈ 19 TB/sthe small tiles currently being computed

Every computation reads its inputs from HBM into SRAM, computes, and writes results back. An operation is memory-bound when moving the data takes longer than the arithmetic. Softmax is a typical case: it does only a few FLOPs per number but must read and write all T2 numbers.

Key ideaOn a GPU, the cost of an operation is often the bytes it moves, not the FLOPs it does. Making attention faster therefore means moving fewer bytes, even if that costs some extra arithmetic.

79FlashAttention: Exact Attention in Tiles

FlashAttention (Dao et al., 2022) combines the two previous bytes. It cuts Q into blocks of rows and K,V into blocks of rows, loads one block of each into fast SRAM, and uses online softmax (§78) to update each Query row's m, ℓ and o. The full T×T matrices S and A are never written to HBM.

for each Q block Qb:for each K/V block (Kc,Vc):Sbc=QbKc⊤dk,update (m,ℓ,o)b with Sbc,Vc
Qb: a block of Br Query rows · Kc,Vc: a block of Bc Key/Value rows · Sbc: a small Br×Bc tile of scores, which exists only in SRAM.
In wordsCompute the attention matrix one tile at a time, fold each tile into the running softmax at once, and throw it away.
  • Exact. The result equals standard attention up to floating-point rounding. It is a different order of computation, not an approximation.
  • Memory. Besides the output, it keeps only m and ℓ per row: 8,192 numbers for T=4,096, instead of the 16,777,216 scores per head.
  • Backward pass. Training needs A to compute gradients. FlashAttention recomputes the tiles from Q, K and the stored m,ℓ instead of storing A. That is extra FLOPs, but fewer bytes moved, which is the right trade according to §77.
HedgeThe paper reported wall-clock speed-ups of several times for attention itself, and 15% to about 3× end-to-end on the benchmarks it tested. FlashAttention-2 (2023) and -3 (2024) improved the work split for newer GPUs. Real gains depend on the hardware, sequence length and head size. The FLOP count stays ∝T2, so FlashAttention makes long contexts affordable but not cheap.
Shape checkSRAM holds Qb (Br×dk), Kc and Vc (Bc×dk), one tile (Br×Bc) and the running ob (Br×dk). Block sizes are chosen so that all of this fits in about 100 KB.

80Sliding-Window and Sparse Attention

FlashAttention keeps all T2 comparisons. The other route is to compare fewer pairs. In sliding-window attention each token attends only to itself and the w−1 tokens before it:

Maskij={0if i−w<j≤i−∞otherwise
w: window size · the mask is added to the scores before softmax, exactly like the causal mask of §28, which is the special case w=T.
In wordsLook back at most w−1 tokens; everything older is blocked.

Worked example. With T=8 and w=3, causal attention computes 36 pairs and the window computes 21. For large T the cost per token is w rather than up to T, so the total grows like T⋅w instead of T2, and the KV cache only has to keep the last w tokens (a “rolling buffer”).

Layers widen the view. Token i in layer 2 attends to tokens up to w−1 back, and each of those already contains information from w−1 further back from layer 1. After L layers information can travel up to L(w−1) positions: 4 after 2 layers and 6 after 3 in the example. Mistral 7B uses w=4,096 with 32 layers, a theoretical reach of about 131,072 tokens. That is an upper bound on how far information can flow, not a guarantee that it does.

Other sparse patterns. Longformer and BigBird (2020) combine a local window with a few global tokens that every token can see (and BigBird adds some random pairs). Several recent models alternate layers: some layers use a sliding window and others full attention (Gemma 2 is one example), so that some layers can see the whole context while most of them stay cheap.

Shape checkThe score matrix is still written as T×T with −∞ outside the band, but efficient kernels compute only the T×w band.

81Multi-head Latent Attention: Caching a Compressed Vector

GQA shrinks the cache by sharing K/V heads. Multi-head Latent Attention (MLA; DeepSeek-V2, 2024) shrinks it in a different way: for each token it caches one small latent vector, and rebuilds every head's Keys and Values from it with learned up-projections.

κt=xtWDKV,kt(h)=κtWhUK,vt(h)=κtWhUV
xt: the token's 1×D input · WDKV: D×dc down-projection · κt: the 1×dc latent; this is what is cached · WhUK,WhUV: dc×dk up-projections for head h.
In wordsSqueeze each token into a short vector, store only that, and expand it back into Keys and Values when they are needed.

The trick that avoids expanding. A score is qi(h)kj(h)⊤=qi(h)(κjWhUK)⊤=(qi(h)WhUK⊤)κj⊤. The up-projection can be moved to the Query side and merged with the Query weights once, after training. The model then scores directly against the cached latents, without building the Keys. The same is done with WhUV on the output side.

A complication with RoPE. The rotation of §72 depends on position and sits between q and k, so it blocks the merge above. MLA therefore keeps a small separate Key part of size dR that carries RoPE, shared by all heads, and caches it too.

Worked example (DeepSeek-V2's published sizes: H=128 heads, dk=128, dc=512, dR=64), counting cached numbers per token per layer:

The prefix rows also come out identical when the block is run on [<BOS>, Je] alone, which is the causal property that makes caching valid. Note what the cache stores: 2 Key numbers and 2 Value numbers per token, shared by both Query heads.

Check 2: RoPE sees only offsets. Run the whole block again with positions 5, 6, 7 instead of 0, 1, 2. Every Query and Key gets rotated by an extra 5 rad, but all offsets j−i are unchanged. By §72, every score and therefore the whole output must be identical. The largest difference is 0.0e+00 (up to floating-point rounding). With the sinusoidal PE of §12 this check would fail, because the added vectors would change.
